¿Por qué estos servicios?

Justificación técnica de cada decisión

Vercel → Vercel Pro

  • Deploy automático desde GitHub sin configuración
  • Edge Network global (CDN incluido en free tier)
  • Mejor opción para Next.js vs Netlify
  • Migración a Pro solo requiere cambio de plan

Render → Railway

  • Render gratis: cold start tras 15 min inactividad
  • Railway: siempre activo, múltiples instancias
  • Ambos soportan Node.js + conexión privada a MongoDB
  • Migración sin cambiar código, solo variable de entorno

MongoDB Atlas M0 → M10

  • M0: 512 MB gratis, ideal para MVP y primeros usuarios
  • M10: 2 GB, 3 réplicas automáticas, backups diarios
  • Elegido sobre PostgreSQL: esquema flexible (documentos)
  • Driver oficial para Node.js con reconexión automática

Cloudflare (gratuito)

  • CDN + WAF + DDoS protection en un solo servicio
  • Gestión de DNS + SSL automático sin costo adicional
  • Alternativa AWS CloudFront costaría ~$10/mes extra
  • Rate limiting gratuito para proteger la API

Huella de Carbono

Impacto ambiental y medidas de mitigación

Componentes de mayor impacto

  • Railway (backend 24/7): ~0.5 kg CO2/mes estimado
  • MongoDB M10 (3 nodos activos): ~1.2 kg CO2/mes
  • AWS S3 + CloudFront: impacto bajo (serverless)
  • Vercel Edge Functions: muy bajo consumo energético

Medidas de Mitigación

  • Usar región AWS us-west-2 (Oregon, 100% renovable)
  • Railway serverless: escala a 0 si no hay tráfico
  • Cloudflare CDN reduce transferencia desde el servidor
  • MongoDB Atlas en región Iowa (energía renovable)
